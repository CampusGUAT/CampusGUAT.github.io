# 贡献指南

欢迎补充经验、修正错误、更新过期流程，也欢迎提出新的栏目建议。

这里提供两种贡献方式：适合偶尔修改的网页编辑，以及适合持续参与的 Git 工作流。无论采用哪种方式，最终都通过 Pull Request 进入主分支，由维护者审核后合并。

## 方式一：直接在网页上编辑

这是最简单的方式，不需要安装 Git 或配置开发环境。

1. 打开想要修改的文章，在页面底部点击“在 GitHub 编辑本页”。
2. 登录 GitHub；如果你不是仓库协作者，GitHub 会自动在你的账号下创建 Fork 和修改分支。
3. 在 GitHub 编辑器中修改 Markdown 内容。
4. 在页面下方填写简短的修改说明，点击提交修改。
5. GitHub 会引导你创建 Pull Request，补充标题和说明后提交。

如果只是发现问题、暂时不会修改，也可以提交 [内容纠错 Issue](https://github.com/CampusGUAT/CampusGUAT.github.io/issues/new?template=content-correction.yml)。如果想分享一段经验或建议新增主题，可以提交 [内容征集 Issue](https://github.com/CampusGUAT/CampusGUAT.github.io/issues/new?template=content-request.yml)。

## 方式二：使用 Git 在本地编辑

适合需要连续写作、批量修改或希望参与网站维护的贡献者。

### 1. 准备工具

- 注册 [GitHub 账号](https://github.com/signup)。
- 安装 [Git](https://git-scm.com/downloads) 和一个编辑器（推荐 VS Code）。
- HTTPS 和 SSH 都可以连接 GitHub；SSH 不是必须的，初次使用 HTTPS 更简单。

### 2. Fork 并克隆仓库

在 [CampusGUAT 仓库](https://github.com/CampusGUAT/CampusGUAT.github.io) 点击 **Fork**，将项目复制到自己的 GitHub 账号，然后在自己的仓库中点击 **Code**，复制 HTTPS 地址并执行：

```bash
git clone https://github.com/你的用户名/CampusGUAT.github.io.git
cd CampusGUAT.github.io
```

### 3. 安装依赖并本地预览

```bash
npm install
npm run dev
```

浏览器打开终端提示的本地地址。修改 Markdown 后，页面通常会自动刷新。

### 4. 找到正确的文章位置

文章都位于 `docs` 目录中，当前结构大致如下：

```text
docs/
├─ 前言/
├─ 个人分享/
├─ 启发/
├─ 入学/
├─ 学业/
├─ 路线/
├─ 未来/
│  ├─ 考研/
│  └─ 就业/
├─ 生活/
└─ 社团/
```

已有主题直接编辑对应的 `.md` 文件。新增文章时，请先确认归属栏目和文件名，再同步在 `docs/.vitepress/config.ts` 的 sidebar 中加入链接，保持左侧目录顺序清晰。

### 5. 提交 Pull Request

建议先同步主仓库，再创建自己的分支：

```bash
git remote add upstream https://github.com/CampusGUAT/CampusGUAT.github.io.git
git fetch upstream
git switch -c docs/简短主题名
```

完成修改并确认本地构建通过后：

```bash
npm run build
git add .
git commit -m "补充：简短说明修改内容"
git push -u origin docs/简短主题名
```

然后在 GitHub 提示中创建 Pull Request，目标仓库选择 `CampusGUAT/CampusGUAT.github.io` 的 `main` 分支。

## 内容规范

- 尽量注明信息来源、适用校区、适用年级和适用时间。
- 涉及收费、考试、学籍、校规和学校政策，请以学校最新官方通知为准。
- 不发布个人隐私、联系方式、未经证实的传言或侵权内容。
- 经验可以主观，但请明确这是个人经历，不要写成学校官方结论。
- 文件名尽量简洁，使用中文即可；链接和标题要保持一致。

## 提交后如何审核

维护者会在 Pull Request 的 **Files changed** 中检查实际改动，在 **Conversation** 中提出修改意见。通过审核后会选择 **Approve**，再使用 **Squash and merge** 合并到 `main`。合并后 GitHub Actions 会自动构建并部署网站。

如果构建失败、链接失效或信息来源不清楚，维护者可能会要求修改，或者暂缓合并。
